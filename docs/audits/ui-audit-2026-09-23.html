Where it stands

Governed, not just green.

The engineering underneath was always careful — well-reasoned components, a real test suite, and accessibility work that had been done properly. The gap was governance: nothing enforced that two pages lay out the same way, that a claim on one page matched the same claim on another, or that a table meant anything with the colour taken away. Those three gaps produced every finding below. All three now have a mechanism behind them instead of a convention.

The features grid

Nine tiles in a six-column grid.

The "Feature sections" band renders nine coloured tiles into .mv-cols-6. Measured: six columns of 196px, two rows, three tiles in the last row, left-aligned inside a centre-aligned section. Three problems stack here, and together they are what makes the page read as a set of arbitrary headline features rather than a table of contents.

  • The grid is ragged by construction. Nine into six leaves a half-empty row. At 960px it becomes three columns and resolves cleanly; at desktop and below 720px it does not.
  • Six hues across nine index tiles encode nothing. Colour rotates for rhythm here by design, but at this density and this size — 12px labels on nine saturated fields — it reads as nine equally-weighted categories with nine meanings. The source comment reasoning about the colour choices describes tile adjacencies that a six-column grid does not produce.

Accessibility

What axe cannot see.

Every automated check passes. These are the defects that survive a green suite because empty table cells and removed disclosure markers are valid HTML. Cell contents below were read out of the live DOM with innerText — what a screen reader gets.

Critical

The pricing comparison matrix is blank to a screen reader

FeatureMatrix.astro

Forty of the forty-three rows carry availability as a Lucide check that ships aria-hidden="true". Read from the live page, a row comes back as "Product + variant sync" | "" | "" | "" | "". The three rows with literal text ("1", "5", "Unlimited") are the only ones a non-sighted visitor can use. The entire plan comparison — the page's commercial argument — conveys nothing.

Critical

The /alternatives comparison is worse — yes and no are both empty

alternatives/index.astro

The ARIA-role table renders both "yes" and "no" as aria-hidden check and x glyphs, so "Real-time inventory" | "" | "" | "Batch sync" | "" — Manuva's yes and a competitor's no are indistinguishable. The table reads as though nobody has anything. Fix both tables the same way: a visually-hidden "Included" / "Not included" span beside the glyph, or an aria-label on the cell.

Medium

No row headers in any of the three tables

markup

Row labels ship as <td>, not <th scope="row">, and the nine category bands are <td colspan="5"> rather than <th colspan="5" scope="colgroup">. In a forty-three-row table that removes the only context a cell-by-cell reader has. The two per-competitor tables on the comparison pages have the same issue, though their cells at least carry real text.

Medium

Mobile loses 38 of 43 comparison rows, and 3 of the 5 it keeps are empty

responsive

Below 720px the matrix is replaced by four per-plan cards of five rows each. Read from the live page at 517px: "Growth | Locations: | 5 | BOM versions: | Production orders: | Variants: | Support: | Email" — three labels with nothing after them, because the value is an aria-hidden tick. Separately, "Production orders" and "Variants" are a tick on all four plans, so two of the five rows in a card headed by differentiators differentiate nothing.

Medium

No FAQ anywhere on the site looks expandable

site.css

.site-faq-q sets list-style:none and defines no ::before or ::after replacement, so the native disclosure triangle is removed and nothing takes its place. Verified in the browser: before:"none" after:"none". Affects the five-item FAQ on /pricing and the four-item FAQs on both comparison pages — every question reads as a plain heading.

Footer.astro

Already right

What not to touch.

Stated plainly because it is unusual to find this much of it intact, and because the fixes above should not disturb any of it.

  • Axe reports zero WCAG A or AA violations across all nine routes. Twenty-three of twenty-three accessibility e2e tests pass, including the drawer focus trap in both directions, Escape-to-close with focus return, the skip link as first tab stop, scroll-lock compensation, and reduced-motion.
  • Structure is clean. No heading-order skips on any page, exactly one h1 per page, no duplicate ids, no image without alt, no empty link. Every internal link and every in-page anchor across all nine routes resolves — including the six cross-page #contact links.
  • Contrast holds where measured. Domain tile inks run 4.60:1 to 15.62:1. The matrix check glyph measures 3.37:1 against a 3.0 non-text floor. Nothing sampled failed.
  • The arithmetic is exact. Annual billing lines ($1,188 / $2,988 / $5,988) reconcile to the monthly figures, and the MRPeasy per-seat table and all six of its delta figures are correct at $49/user/month.
  • The YouTube facade holds. No third-party request on load on any route except the known font gap, enforced by a test that would catch a regression.
  • The component reasoning is sound. Field and Panel merge caller styles rather than dropping them, Icon fails the build on an unknown glyph rather than rendering nothing, and the pricing toggle is progressive enhancement over server-rendered defaults.
How it was done

Six batches, verified at each step.

In this order, because each batch was independently shippable and the later ones depended on the earlier ones holding.

1

The nine copy corrections

copy

Five self-contradictions and four internal sales notes. String edits across four files, no layout risk, and the findings that cost a sale. Currency resolved to AUD on the author's instruction, with the competitor figures now labelled as their USD list price so the comparison is not silently across two currencies.

2

The three tables

a11y

Accessible names via role="img" + aria-label rather than visually-hidden text — the parity gate compares table cells on extracted text, so added text, hidden or not, would have tripped it. Plus th scope="row", scope="colgroup", and real rowgroups on the ARIA table.

3

The hero contract

css

Six near-identical per-page hero rules collapsed into one shared block. /alternatives got the panel it never had. The home page stays its own shape, asserted rather than assumed, because its title width calc and the lime mark's nowrap are load-bearing against a defect already fixed twice.

4

The heading scale, the grid and the plan cards

layout

CTA band 88px → 52px, "Explore further" 12px → 40px, nine tiles into a centred three-column wrap, and the Enterprise card's missing row reserved so four CTAs form a line. The features index now reads its labels from the nav's own array, so the two cannot disagree again.

5

Three colour fields, then three contrast fixes

design

Adding the fields immediately broke axe on inks written for paper. Fixed by inheriting each field's paired ink — the rule the project had already written down.

6

Twenty-one tests

tests

The hero contract, the heading scale in both directions, tile hue adjacency at three breakpoints, the centred short row, and the plan-card CTA line. Every one of them measures something no existing gate could see — which is why all of it shipped in the first place.
